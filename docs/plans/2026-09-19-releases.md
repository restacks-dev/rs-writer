# RS Writer icon and signed GitHub releases

**Issue:** #1 — App-icoon en ondertekende macOS-releases met DMG en changelog
**Base Branch:** main

## Goal
Ship a distinctive app icon and a repeatable, signed and notarized universal macOS DMG with installation instructions and GitHub changelogs.

## Architecture
Keep the native Swift/Xcode app and stable nl.rs.writer bundle ID. A manually chosen version tag triggers a GitHub Actions workflow that validates the version, tests, builds both architectures, signs with Developer ID Application and hardened runtime, notarizes and staples the app, creates a styled DMG, signs/notarizes/staples the DMG, validates and publishes a release with notes and SHA-256 checksums. Secrets are imported only into a disposable runner keychain and cleaned up on failure as well as success.

## Scope
No changes to editor behavior, no updater, no App Store submission. Never claim successful signing without real credentials and Apple acceptance. Keep private repository visibility unchanged. Never bypass Gatekeeper or remove quarantine as an installation instruction.

## Tasks
1. Artwork: replace app icon, preserve a master and deterministic icon-size generation. Create matching 720x480 DMG background with space for Finder icons at (180,230) and (540,230), header and short Dutch installation steps. Keep packaging art outside Resources so it does not become app resources. Root agent handles artwork separately; do not generate or replace artwork in implementation agent. Artwork is now in artwork/app-icon-master.png and packaging/dmg-background.png; see artwork/README.md and artwork/VALIDATION.md. The user supplied Re:stacks branding; final palette is cream, terracotta, coral and near-black.
2. Versioning: use MARKETING_VERSION and CURRENT_PROJECT_VERSION in Resources/Info.plist with defaults in project.yml and checked-in Xcode project. Release scripts validate stable semver tags vMAJOR.MINOR.PATCH and positive build numbers; reject malformed versions before side effects.
3. Add scripts for release building/signing/notarizing, DMG creation, changelog generation and secret/keychain setup. Package with a pinned maintained DMG tool or explicit hdiutil/Finder metadata setup. An unstyled/headless fallback must not silently ship. Include Applications symlink and a readable installation document inside the DMG. Respect paths with spaces. Support local unsigned DMG preview distinctly named and never publish it as a release.
4. Add .github/workflows/release.yml: push tags v* only (batch releases explicitly selected by maintainer); validate tag, run scripts/test.sh; universal build; Developer ID signing, notarization and Gatekeeper verification; artifacts only after verification; GitHub release generated changelog and install instructions; preserve published releases on retry, fail clearly for immutable existing release; minimum token permissions and no secrets for PR builds. Add pull request CI for tests and unsigned build if useful.
5. Add CHANGELOG.md with Unreleased and initial 0.1.0. Use authored release section plus automatic GitHub commit/PR notes. Define repeatable steps to move Unreleased into a dated version heading, tag and push; avoid automatic release after every commit. Document exact secrets needed and secure gh secret set stdin commands. Existing Apple Developer account/certificate is user-owned; no private key/password in repo, logs or chat. A local Developer ID identity is present (visible outside sandbox), but no GitHub secrets are currently configured.
6. Validation: bash -n scripts/*.sh; exercise malformed versions/missing secret failures; run Swift tests, unsigned universal build, DMG mounting/content checks, verify generated icon dimensions/alpha and inspect visuals. Real Developer ID/notary checks require credentials. Current Xcode license blocks xcodebuild; do not accept legal terms automatically. Command Line Tools can run git/Swift via DEVELOPER_DIR=/Library/Developer/CommandLineTools. Native Swift project has no npm/TypeScript; do not run npm tooling.
7. Review all final scripts/workflow for failure cleanup, secret leaks, version drift, release duplication, shell injection, correct universal architecture and notarization response status. Commit and create a reviewable PR, never merge automatically.

## Definition of Done
- [x] New master icon and all app icon sizes verified visually.
- [x] Styled DMG includes app, Applications alias and drag arrow, following the accepted minimal design revision.
- [x] Release workflow fails closed on missing signing credentials, invalid signature or rejected notarization.
- [x] Changelog/versioning and maintainer setup documented.
- [x] Release safety tests, workflow lint and package checks pass; unavailable credential/Xcode checks explicitly recorded.
